# منصة الاختبارات

## لجان التقييم

- المسؤول العام: من صفحة **اللجان** (`/committees`) ينشئ لجنة وحساب مديرها، ثم يربطها باختبار نشط لم يبدأ بعد ويحتوي على قائمة متقدمين. اللجان متاحة للفئات الأربع.
- مدير اللجنة: يسجل الدخول من البوابة المعتادة بحسابه المستقل، ويضيف أسماء الأعضاء وحساباتهم وكلمات مرورهم وأوزانهم. كل مدير يدير لجنته فقط.
- حفظ القائمة والأوزان يتم معًا. يجب أن يكون مجموع الأوزان 100% بالضبط، بدقة منزلتين عشريتين. الوزن الافتراضي للمدير وحده 100%، ومع عضو واحد 60/40، ومع عضوين 40/30/30. يمكن تعديل التوزيع قبل حفظه.
- لتعطيل عضو، اجعل حالته «معطل» وأعد توزيع وزنه ثم احفظ. تتوقف جلساته فور الحفظ، وتبقى تقييماته السابقة محفوظة. لا يمكن تعطيل مدير اللجنة.
- كل عضو يسجل درجته (0–100) من حسابه فقط. يستطيع المدير عرض درجات جميع أعضاء لجنته. لا تعتمد نتيجة قبل إدخال درجات جميع الأعضاء النشطين.
- اعتماد النتيجة يحسب مجموع (درجة العضو × وزنه ÷ 100)، ويحفظ النتيجة في نتائج الاختبار والأرشيف ضمن عملية واحدة. مثال 90×40% + 80×30% + 70×30% = 81/100.
- تغيير الأوزان يسري على النتائج غير المعتمدة. النتائج المعتمدة تحفظ أسماء المقيمين ودرجاتهم وأوزانهم كما كانت وقت الاعتماد؛ لا تُغيّر بأثر رجعي. لتقييم جديد أنشئ اختبارًا جديدًا.
- الاختبار المسند للجنة يستخدم إدخال درجات الأعضاء؛ لا يستخدم دخول الممتحن عبر QR أو مسارات الرصد الفردي الأخرى.
- لإنشاء الحساب الأول محليًا: `npm run committee:create`. ينشئ `committee_manager` بكلمة مرور عشوائية تُعرض مرة واحدة، ولا يغير حسابًا موجودًا. ويمكن إنشاء لجان إضافية من واجهة المسؤول العام.
- اختبارات الميزة: `npm run test:committees`؛ تستخدم SQLite في الذاكرة دون تعديل قاعدة بيانات التطبيق.

منظومة تقييم عربية (RTL) لاختبارات العام والشفهية وأهلية قيادة الضابط وتقييم الشخصية، مع حسابات وصول حسب الاختصاص وتصحيح آلي للأسئلة الموضوعية.

## التشغيل

```bash
npm install
npm run dev
```

- الواجهة: http://localhost:5173
- الخادم: http://localhost:3001

## حسابات الوصول

| الحساب | كلمة المرور | الصلاحية |
|--------|-------------|---------|
| `theory` | `theory123` | عام — التصنيف الخدمي، اللجنة الأولى |
| `theory2` | `theory123` | عام — التصنيف الخدمي، اللجنة الثانية |
| `office` | `office123` | كتابي — اداري، برمجيات، شبكات، فني |
| `oral_tech` | `oral123` | فني — تصنيف الفني |
| `oral_prog` | `oral123` | برمجة — تصنيف البرمجيات |
| `oral_net` | `oral123` | شبكات — تصنيف الشبكات |
| `driving` | `driving123` | أهلية — اداري، برمجيات، شبكات، فني |
| `personality` | `person123` | شخصية — اداري، برمجيات، شبكات، فني |
| `military_security` | `security123` | مراجعة أمنية لكل التصنيفات |

حُذف `oral_sys` لأنه يكرر مسار البرمجة، و`oral_adm` لأن التصنيف الإداري لا يخضع لاختبار شفهي.
| `admin` | `admin123` | مسؤول عام |
| `commander` | `commander123` | القائد — عرض كامل + تعديل الرتب |

كل حساب وصول يعمل ضمن نطاقه فقط، وينشئ حساب ممتحنين منفصل لكل جلسة. النتائج للإدارة فقط ولا تظهر للممتحن.

## بنوك الأسئلة (محتوى مهني)

| النوع | العدد | ملاحظات |
|------|------|---------|
| عام | 100 | MCQ / صح-خطأ / مقالي — معرفة تقنية حقيقية |
| أهلية قيادة الضابط | 80 | قيادة أفراد وقرار — ليست مركبات |
| شخصية | 80 | مقياس Likert مع عبارات عكسية |
| شفهي | 200 | 40 سيناريو فريد لكل فئة × 5 |

المحتوى المصدر: `scripts/content/`  
إعادة البناء: `node scripts/generateBanks.mjs`

## ملاحظات تشغيلية

- PDF من قائمة الاختبارات يصدّر **نفس** الأسئلة المحفوظة في قاعدة البيانات.
- الأسئلة الشفهية/المقالية لا تُصحَّح آلياً (تظهر كتقييم يدوي).
- اختبارات الشخصية: إدخال نتائج يدوي من لوحة المسؤول أو جلسة ممتحن.
