# تشغيل منصة الاختبارات في بيئة فعلية

## متطلبات التشغيل

- Windows 10/11 أو Windows Server، وNode.js 24 LTS.
- قرص محلي سريع لقاعدة البيانات، ومسار ثانٍ على جهاز أو مخزن شبكي للنسخ الاحتياطية.
- HTTPS أمام المنصة عبر Caddy أو Nginx. لا تُفتح مشاركة الشاشة خارج HTTPS.
- تركيب واحد للخادم مع SQLite. لا تشغّل نسختين من API على ملف قاعدة البيانات نفسه.

انسخ `.env.example` إلى `.env.production` وغيّر الأسرار والمسارات. يقرأ مشغّل الإنتاج هذا الملف قبل الإقلاع. في أول تشغيل فقط، إن لم تُحدد كلمات المرور الأولية، يكتب النظام كلمات عشوائية في `data/initial-credentials.txt` بصلاحيات مقيدة. يستطيع صاحب الحساب تغيير كلمة مروره اختياريًا من داخل المنصة. احفظ ملف البيانات الأولية في مكان آمن ثم احذفه من الجهاز بعد تسليم الحسابات.

مدة جلسة العاملين الافتراضية 30 يومًا وتتجدد كل عشر دقائق أثناء الاستخدام وعند الرجوع إلى التبويب، لذلك لا تنقطع المقابلة الطويلة. يمكن ضبطها بالثواني عبر `SESSION_MAX_AGE_SECONDS` بحد أدنى يوم واحد. تحفظ صفحة المقابلة كل تعديل غير معتمد تلقائيًا في قاعدة البيانات وتستعيده بعد تحديث الصفحة.

كلمة مرور حساب `admin` لا يمكن تغييرها من الواجهة أو API. يغيرها المطور محليًا من الجهاز المضيف فقط بالأمر `npm run admin:password`؛ يخفي الأمر الأحرف أثناء الكتابة ويلغي الجلسات القديمة ويسجل العملية. يستطيع `admin` إدارة كلمات مرور بقية الحسابات ومراجعة سجل التغييرات من صفحة «إدارة كلمات المرور».

## البناء والتشغيل

```powershell
npm ci
npm run check
npm start
```

`npm start` يشغّل ملفات `dist` والخادم من منفذ واحد، ويعيد تشغيل عملية الخادم إذا خرجت بصورة غير متوقعة. لتسجيله عند إقلاع Windows، افتح PowerShell كمسؤول مرة واحدة وشغّل:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install-windows-service.ps1
```

وجّه Caddy أو Nginx إلى `http://127.0.0.1:3001`، واضبط `APP_ORIGIN` على عنوان HTTPS النهائي و`TRUST_PROXY` على الوكيل الموثوق فقط. لا تستخدم خادم Vite أو نطاقات ngrok في التشغيل الفعلي.

## تشغيل QR داخل LAN/Wi-Fi

احجز عنوانًا ثابتًا لجهاز الخادم في الراوتر، ثم ثبّت Caddy وشغّل PowerShell كمسؤول:

```powershell
winget install --id CaddyServer.Caddy --exact
.\scripts\setup-lan-https.ps1 -PublicHost 192.168.1.20 -InstallStartupTasks
```

يضبط السكربت `PUBLIC_APP_URL` و`APP_ORIGIN`، وينشئ أسرارًا عشوائية عند غيابها، ويقصر Express على loopback، ويفتح 443 للشبكة الخاصة فقط، ويسجل المنصة وCaddy للتشغيل عند إقلاع Windows التالي. يحتوي QR على العنوان المحلي الرسمي ويستمر استهلاكه ذريًا لمرة واحدة بالطريقة نفسها.

يستخدم Caddy شهادة داخلية. ثبّت شهادة الجذر التي يعرض مسارها السكربت على أجهزة الاختبار الموثوقة قبل يوم الاختبار؛ من دون الوثوق بها ستظهر رسالة شهادة وقد لا تعمل مشاركة الشاشة. اختبر الوصول مع فصل الإنترنت للتأكد أن DNS أو الشهادة لا يعتمدان على خدمة خارجية. يجب أن تسمح شبكة Wi-Fi للأجهزة بالوصول إلى الخادم وألا تفعل عزل العملاء.

مدد QR الافتراضية هي دقيقة لكل سؤال نظري، وخمس دقائق لكل سؤال شفهي أو قيادة، و90 ثانية لكل سؤال شخصية. الخادم يحفظ الموعد النهائي ويستعيده بعد إعادة التشغيل؛ لا تعيد الصفحة بدء المؤقت. تحفظ الإجابات على الخادم بعد كل تغيير، وتعيد الواجهة المحاولة كل خمس ثوانٍ وعند عودة الشبكة. جلسات المقيمين غير مقيدة بهذا المؤقت، وتبقى جلسة الحساب 30 يومًا مع التجديد أثناء الاستخدام.

## فحص الصحة والتعافي

- `GET /api/health/live` يتحقق أن العملية تستجيب.
- `GET /api/health/ready` يتحقق من قاعدة البيانات، الترحيلات، المفاتيح الأجنبية، مساحة القرص وحداثة النسخ.
- `npm run load:test` ينفذ فحصًا متزامنًا من 100 اتصال على بيئة الاختبار.
- النسخ الآلية تحتفظ بأحدث النسخ وتتحقق من SHA-256 و`integrity_check`. اضبط `ARCHIVE_BACKUP_MIRROR_DIR` على مخزن منفصل فعليًا، وطبّق عليه تشفير القرص/المجلد وسياسة كتابة غير قابلة للحذف من حساب الخدمة.
- اختبر الاستعادة فصليًا إلى مسار جديد باستخدام `restoreBackup`، ثم قارن أعداد `attempts` و`assessment_archive` و`archive_versions` قبل اعتماد الاختبار.

قبل التحديث، أوقف الخدمة وخذ نسخة يدوية. بعد التحديث شغّل `npm ci` ثم `npm run check` وابدأ الخدمة؛ ترحيلات قاعدة البيانات مرقمة وتوقف الإقلاع عند أي فشل بدل متابعة العمل بمخطط جزئي.
