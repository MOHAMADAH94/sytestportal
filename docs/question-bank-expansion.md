# توسيع بنك الأسئلة والتعامل مع النقص

أصبح البنك 1462 سؤالًا: 580 نظريًا و530 شفهيًا و176 للقيادة و176 للشخصية. أضيف 472 سؤالًا بنصوص مختلفة، مع إبقاء الأسئلة الـ990 السابقة ومعرفاتها وبياناتها كما هي.

أضيفت 15 فئة وظيفية إلى الست السابقة: حارس، مستخدم خدمات، متابع آليات، عامل صيانة، لوجستي، موظف ديوان، مستثمر حاسوب، فني كهرباء، فني ميكانيك، تقني شبكات، فني إلكترونيات، مهندس مدني، مهندس كهرباء، مهندس ميكانيك، ومهندس اتصالات. التصنيف بحسب مسمى العمل الحالي، وتظل المسميات الأصلية محفوظة في بيانات المتقدمين.

تشمل الإضافة 360 سؤالًا خاصًا بهذه الوظائف، و96 سؤال قيادة وسلوك موزعة على عائلات الخدمات والإدارة والفنيين والهندسة، و16 سؤالًا عامًا في مهارات العمل يمكن استخدامها عند اختيار السماح بالمشترك. أسئلة العائلات مرتبطة صراحةً بالمسميات المعنية ولا تُنسخ كنصوص متكررة لكل مسمى. المحتوى مؤلف لأغراض التقييم المهني ويحتاج مراجعة مختص الجهة لسياساتها ومتطلباتها قبل الاعتماد الرسمي؛ أسئلة الشخصية ليست اختبارًا نفسيًا مقننًا أو أداة تشخيص.

مصادر المحتوى في `scripts/content/expanded*.mjs`، والتعريفات في `shared/additionalJobProfiles.js`. يعيد `npm run banks` بناء ملف الخادم وبنوك الواجهة بمعرفات مستقرة. يبقى المحتوى المحفوظ في الاختبارات والنتائج القديمة مستقلًا عن تغيير البنك.

## الإنشاء دون شرط الكفاية

- إذا طلب المسؤول 20 سؤالًا وكان المتاح 7، يعرض الملخص العددين ويُنشأ الاختبار بالسبعة المناسبة فقط. لا تُكرر الأسئلة داخل المجموعة ولا تُخفف الصعوبة أو الاختصاص خفية.
- إذا لم تتوفر أسئلة لمجموعة، ينشأ الاختبار كمسودة متوقفة. تبقى المجموعات الأخرى محفوظة. تظهر روابط استكمال الأسئلة في شاشة نجاح الإنشاء وقائمة الاختبارات وبطاقات الدخول.
- من «استكمال أسئلة الاختبار» يستطيع المسؤول إضافة أسئلة يدوية بإجابات نموذجية ومعايير، أو إعادة البحث في البنك بعد إثرائه. يدعم استكمال الشخصية عبارات مقياس واتجاهها. لا تشترط إعادة البحث عدد الطلب الأصلي، ولا تنشر الأسئلة اليدوية تلقائيًا في البنك العام.
- تُفتح المسودة بعد استكمال كل المجموعات الفارغة. يمنع الخادم تفعيلها أو إدخال نتيجة لتجاوز نقص المحتوى. لا يجوز تعديل المجموعات بعد بدء الدخول أو التقييم؛ الاستكمال مخصص للمجموعات الفارغة قبل ذلك.
- حسابات التخصص تظل ضمن نطاق صلاحياتها. التخصصات المستحدثة غير المطابقة يديرها المسؤول العام، ولا تُمنح لحساب مختص آخر تلقائيًا.

## المسميات الجديدة

يعرض النظام للمسمى غير المعروف خيار «تخصص جديد — أسئلة يدوية أو مشتركة فقط». يمكن إنشاء مسودة مستقلة ثم استكمالها، أو اختيار تصنيف قائم إذا تحقق المسؤول من تطابق مهام العمل. هذا اختيار خاص بالاختبار ولا يغير مسمى الشخص أو ينشئ تطابقًا دائمًا.

المشترك يحتاج موافقة صريحة ولا يحل محل إثبات الكفاءة التخصصية. لا يسمح البنك بتخزين أسئلة تخصصية تحت تصنيف «غير معروف» ثم توزيعها على جميع المسميات غير المعروفة.

للتطوير اللاحق يُنصح بإضافة سجل تخصصات قابل للإدارة مع مراجعة مرادفات المسميات، ومسار إعداد أسئلة يراجعها خبير الوظيفة قبل نشرها. يمكن دعم هذا المسار باقتراحات آلية مسودة، على أن يتحقق المختص من صحة الإجابات وملاءمة المهارة والصعوبة. يُستحسن أيضًا تنبيه إدارة البنك دوريًا للمسميات المتكررة التي اعتمدت أسئلة يدوية أو استُخدم لها عدد أقل من المطلوب.

## التحقق

تختبر `npm run test:jobs` التغطية وعدم تكرار النصوص، والاختصاصات والمرادفات، وإنشاء الاختبار عند النقص أو انعدام الأسئلة، والاستكمال اليدوي للأنواع الأربعة، والصلاحيات والتراجع عند فشل الحفظ واستكمال البنك الجديد دون تخفيف المرشحات. اختبار API ضمن `npm run test:archive` يتحقق من منع تشغيل المسودة الخالية ثم نجاح استكمالها مع حماية الأرشيف مفعلة.
